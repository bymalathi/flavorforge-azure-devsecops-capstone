# 04 — Azure DevOps Pipeline Variables

## 1. What We Wanted

After creating the FlavorForge Azure DevOps pipeline, the next step was to define the values required by the pipeline stages.

The pipeline needed values for:

```text
Docker Registry Connection
Backend Image Repository
Frontend Image Repository
Container Registry
Image Tag
AKS Resource Group
AKS Cluster
```

These values allow the same pipeline YAML to use the FlavorForge Azure resources during the build, publishing and deployment stages.

---

# 2. Verify the Pipeline Variables

The pipeline variables were configured in the Azure DevOps pipeline.

The pipeline configuration uses variables such as:

```text
dockerRegistryServiceConnection
imageRepositoryBackend
imageRepositoryFrontend
containerRegistry
imageTag
aksResourceGroup
aksClusterName
```

The relationship is:

```text
Pipeline Variables
       ↓
Azure DevOps Pipeline
       ↓
Build / Docker / ACR / AKS
```

---

# 3. Docker Registry Service Connection

The pipeline uses the configured ACR service connection for Docker image publishing.

The variable is:

```text
dockerRegistryServiceConnection
```

Its value points to the Azure DevOps service connection created earlier:

```text
flavorforge-acr-connection
```

The flow is:

```text
Pipeline
   ↓
dockerRegistryServiceConnection
   ↓
flavorforge-acr-connection
   ↓
Azure Container Registry
```

This allows the Docker publishing stage to use the configured registry authentication.

---

# 4. Backend Image Repository

The backend Docker image repository is configured through:

```text
imageRepositoryBackend
```

This variable identifies the backend image repository used by the pipeline.

The flow is:

```text
Backend Source
      ↓
Docker Build
      ↓
imageRepositoryBackend
      ↓
Azure Container Registry
```

The backend image is therefore built and published separately from the frontend image.

---

# 5. Frontend Image Repository

The frontend Docker image repository is configured through:

```text
imageRepositoryFrontend
```

The flow is:

```text
Frontend Source
      ↓
Docker Build
      ↓
imageRepositoryFrontend
      ↓
Azure Container Registry
```

This keeps the frontend and backend container images separate.

---

# 6. Container Registry

The pipeline also uses a variable for the Azure Container Registry:

```text
containerRegistry
```

The FlavorForge registry is:

```text
flavorforgeacr2026ms
```

The image publishing flow is:

```text
Frontend Image ──┐
                 ├──→ flavorforgeacr2026ms
Backend Image ───┘
```

The registry stores the Docker images generated by the pipeline.

---

# 7. Image Tag

The pipeline uses the Azure DevOps build ID as the image tag:

```text
imageTag
```

The value is based on:

```text
$(Build.BuildId)
```

The flow is:

```text
Azure DevOps Build
        ↓
Build.BuildId
        ↓
imageTag
        ↓
Docker Image
```

This gives each pipeline build an identifiable image tag.

---

---

# 21. Why Variables Were Used

Instead of repeatedly writing resource values throughout the pipeline YAML, the pipeline uses variables.

For example:

```text
flavorforge-rg
```

is represented by:

```text
aksResourceGroup
```

and:

```text
flavorforge-aks
```

is represented by:

```text
aksClusterName
```

This keeps the pipeline configuration organized and makes the resource values reusable across stages.
